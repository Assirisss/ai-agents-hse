# Личный ассистент · учебный проект по курсу «AI-агенты»

Проект команды из четырёх человек. Подготовлены React-оболочка с боковым меню в стиле SecondBrain, общая служба поиска трендов и финансовый MVP; функциональность остальных предметных модулей уточняется.

Идея — личный ассистент, объединяющий данные и дела из разных сфер жизни. Основной принцип: максимально используем детерминированные автоматизации и добавляем AI только для задач, которые ими не покрываются.

Репозиторий: [Assirisss/ai-agents-hse](https://github.com/Assirisss/ai-agents-hse).

**Дела и календарь · Финансы и инвестиции · Спорт и питание · Гардероб**

Планируем собственный сайт и взаимодействие через Telegram. Для проверки используем одинаковые данные. Утренний отчёт оставляем дополнительной функцией; тренды рассматриваем как общую возможность для разных разделов.

## Как работаем над идеей

1. Обсуждаем один блок вопросов за раз, начиная с проблемы и пользователя.
2. Фиксируем ответы в документах. Предположения явно отмечаем и проверяем.
3. Описываем конкретный пользовательский сценарий от входных данных до результата.
4. Выбираем небольшой MVP и определяем, как проверить его качество.
5. Рисуем схемы пользовательского сценария, работы агентов и компонентов системы в Mermaid.
6. Выбираем архитектуру и разбиваем MVP на задачи с понятным результатом и условиями приёмки.
7. Согласуем интерфейсы между частями системы и распределяем работу между четырьмя участниками.

На следующих этапах добавим требования, архитектуру, инструкции запуска и задачи. Каждая задача должна содержать контекст, входные и выходные данные, зависимости и условия готовности, чтобы участник команды мог работать над ней со своим AI-агентом.

## Статус

Согласованы четыре продуктовых блока и каналы взаимодействия. Создан frontend на React + TypeScript + Vite. Общий поиск трендов доступен через экран, HTTP API и инструмент `search_trends` для будущего оркестратора. Backend этой службы — Node.js + TypeScript + Fastify. Добавлены профиль, контекст разделов, SQLite-память, веб-поиск, Crossref и выбор инструментов через OpenRouter или Ollama. Обязательных платных API нет; по умолчанию для OpenRouter используется бесплатный маршрут. Агентная архитектура остальных областей и состав первой демонстрации уточняются.

## Финансовый блок

Учёт доходов, расходов и переводов, черновики по тексту и фото чека, статистика, акции MOEX TQBR и фактическая ежедневная сводка Telegram. Данные — Postgres; запись после подтверждения. Текстовая и визуальная модели настраиваются отдельно, расчёты и котировки работают без LLM. Инвестиционных рекомендаций нет. [Инструкция](docs/finance.md).

При запуске Node.js напрямую запустите из корня `docker compose up -d postgres`, задайте `DATABASE_URL` в backend `.env` по примеру. Общий бот запускается вместе с backend; нужны токен и привязка через сайт. Для отправки ежедневной сводки в 21:00 Москвы отдельно запустите `npm run finance:worker` из backend.

## Запуск через Docker

Нужны Docker Desktop или Docker Engine с [Compose 2.24+](https://docs.docker.com/compose/how-tos/environment-variables/set-environment-variables/). Все команды выполняются из корня репозитория.

Создайте корневой `.env`, если его ещё нет:

```sh
test -f .env || cp .env.example .env
```

В Docker настройки читаются из корневого `.env`; `backend/.env` используется при запуске Node.js напрямую. Укажите API-ключи для нужных моделей и токен Telegram, если будете ими пользоваться. Без ключей доступны ручной учёт, расчёты, календарь и котировки; модели требуют настроенного провайдера. Для одного Telegram-токена запускайте только один backend.

Соберите образы и запустите сайт, API и отдельную базу Postgres:

```sh
docker compose up -d --build --wait
docker compose ps
curl --fail http://localhost:5173/api/health
```

Сайт: **http://localhost:5173**. API доступен через `/api` на том же адресе. Миграции применяются при запуске backend. Dockerfile в корне содержит отдельные сборки `backend` и `frontend`; Nginx раздаёт сайт и проксирует API, включая потоки ответов агентов и долгое распознавание изображений.

Если порты 5173 или 5432 уже заняты, задайте в корневом `.env` `APP_PORT=5174`, `POSTGRES_PORT=5433`, `PLANNING_PUBLIC_URL=http://localhost:5174`. После этого сайт и проверка здоровья доступны на порту 5174.

Для демонстрационных финансовых данных:

```sh
docker compose exec backend node dist/backend/src/finance/manage.js --seed-demo
```

Откройте **http://localhost:5173/?financeProfile=demo** (либо выбранный `APP_PORT`). Команда заменяет только демопрофиль. У Docker отдельные базы и каталог чеков; локальные данные из `backend/data` и локального Postgres автоматически не переносятся.

Для ежедневных сводок котировок задайте `TELEGRAM_BOT_TOKEN` и `TELEGRAM_BOT_USERNAME` в корневом `.env`, привяжите профиль на сайте и добавьте акции в список наблюдения. Затем включите дополнительный worker:

```sh
docker compose --profile notifications up -d --build
```

Просмотр логов и остановка:

```sh
docker compose logs -f backend frontend
docker compose --profile notifications down
```

Именованные тома сохраняют Postgres, SQLite, ключ шифрования и чеки после остановки. После изменения `.env` пересоздайте backend командой `docker compose up -d --force-recreate backend`; если включён worker, также выполните `docker compose --profile notifications up -d --force-recreate finance-worker`.

## Локальный запуск без Docker

Node.js 24 LTS и npm. В первом терминале из корня репозитория:

```sh
cd backend
npm ci
npm run dev
```

Во втором терминале из корня репозитория:

```sh
cd frontend
npm ci
npm run dev
```

Откройте адрес, который напечатает Vite, обычно `http://localhost:5173`. Поиск трендов находится в боковом меню «Инструменты»: можно выбрать явно обозначенный демонабор или живые RSS-источники и поиск в интернете. Профиль, контекст разделов и память доступны на том же экране; вызовы модели включаются отдельно.

Дела и календарь — `frontend/src/modules/planning/`, финансы — `finance/`, спорт и питание — `health/`, гардероб — `wardrobe/`. Общий экран поиска — `trends/`; типы интеграции — `shared/trends.ts` в корне проекта. [Подробности для команды](frontend/README.md).
