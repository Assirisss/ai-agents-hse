# Чат поиска трендов: сначала детерминированные инструменты

Чат находится в разделе «Поиск трендов», рядом с прежним экраном исследования. Можно задавать тему, менять период, обсуждать сохранённый отчёт, фильтровать источники и делать закладки. Свободный диалог использует настроенный на backend `ResearchPlanner`. Новый провайдер или платный сервис для чата не требуется.

## Применённые практики

Изучены первичные материалы [Anthropic о проектировании инструментов](https://www.anthropic.com/engineering/writing-tools-for-agents), [об управлении контекстом](https://www.anthropic.com/engineering/effective-context-engineering-for-ai-agents) и [OpenRouter об ограниченном цикле tool calling](https://openrouter.ai/blog/tutorials/build-tool-calling-agent-loop/).

Применение в проекте:

- У каждого инструмента одна понятная операция, строгая схема и описание эффекта. Изменение параметров не запускает поиск.
- Простые команды распознаются небольшим явным набором правил. Неизвестные формулировки передаются модели либо получают честную подсказку, если модель выключена.
- История диалога хранится на сервере. Модель получает последние десять сообщений текущего режима, параметры, выборку источников и сводку активного отчёта; полные прошлые отчёты автоматически в контекст не загружаются.
- Изменяющие действия и повторная отправка контролируются обычным кодом: версия диалога, идентификатор сообщения, транзакция и запрет параллельной записи в один диалог.
- Ответ инструмента считается данными. Идентификаторы отчётов и источников проверяются в текущем профиле; произвольные файлы и URL не принимаются.

Это наша адаптация рекомендаций. Атомарная запись в SQLite и правила разрешения нового поиска — инженерные решения проекта, а не обязательные требования указанных авторов.

## Контракты инструментов

| Инструмент | Вход | Детерминированный результат и эффект |
| --- | --- | --- |
| `update_brief` | `query?`, `domain?`, `windowDays?` | Проверяет период 1–30 дней и область; меняет параметры текущего диалога. Новую тему берёт из текущего сообщения пользователя, а не приватного профиля. Интернет не вызывает. |
| `research_now` | `{}` | Не более одного исследования за сообщение, по текущим параметрам. Обычный запрос темы тоже разрешает исследование, без обязательного слова «найди». Внутри вызывается существующий обычный сценарий с `enableAi=false`: вложенный агент не запускается. |
| `list_reports` | `query?` | Находит отчёты текущего профиля и режима. Возвращает настоящие идентификаторы. |
| `filter_sources` | `reportId?`, `query?`, `onlyDated?`, `onlyRecent?`, `onlyRead?`, `kind?`, `publisher?`, `limit?`, `reset?` | Фильтрует сохранённые источники, убирает дубли URL, применяет лимит 1–20 и стабильную сортировку. Интернет не вызывает. Фильтры сохраняются в диалоге. |
| `inspect_source` | `sourceId`, `reportId?` | Возвращает сохранённый текст до 4500 символов или фрагмент с указанием типа основания. Не выполняет новое чтение страницы. |
| `compare_reports` | `leftId`, `rightId` | Сравнивает нормализованные ссылки. Демо/live и разные темы напрямую не сопоставляет. Новая ссылка не объявляется ростом популярности. |
| `save_source` | `sourceId`, `reportId?` | Подготавливает закладку существующего источника только по прямой просьбе сохранить. Повторный URL не создаёт дубль. |
| `list_saved_sources` | `{}` | Возвращает до 100 последних закладок текущего профиля и режима. |
| `finish_chat` | `text`, `citations` | Проверяет ссылки на существующие источники; непроверенные URL в тексте отклоняет. Формирует сообщение. |

Параметры `profileId`, путь к базе и адреса страниц модель в аргументах инструментов не задаёт. Все эффекты проходят через общий реестр `createTrendChatTools`; его можно тестировать и использовать без LLM.

## Примеры без модели

- `Привет` — описание доступных действий.
- `/тема AI agents` — установить тему без поиска.
- `за месяц`, `за 14 дней`, `/период 7` — изменить период без поиска.
- `/область здоровье` — выбрать предметную область.
- `Найди силовые тренировки за 14 дней` — задать параметры и выполнить исследование.
- `Обнови поиск` — повторить исследование по текущим параметрам.
- `Только с датой`, `Только свежие`, `Только прочитанные`, `Только научные` — фильтровать текущие источники.
- `Покажи все источники` — сбросить фильтры.
- `/источник 1`, `/сохранить 1` — использовать номер из последнего списка источников в ответе.
- `/история`, `/закладки` — посмотреть сохранённые данные.
- `/сравнить 1 2` — сравнить два отчёта по номерам из последней показанной истории. Идентификаторы для инструментов подставляет код.

Для произвольных вопросов вроде «Почему этот источник полезен для моей цели?» модель выбирает нужные инструменты. Новая тема, например «Стил мужской 2026 год», разрешает исследование без дополнительного подтверждения. Модель задаёт тему из сообщения через `update_brief` и вызывает `research_now`. Пустая история не является причиной отказываться от поиска. В live с включённым `useWeb` выполняется веб-поиск; без него доступны только RSS, а demo использует учебные данные. Обсуждение существующего источника не запускает новый поиск. Просмотр списка истории сам по себе не прикрепляет все найденные отчёты к свободному ответу; ссылки появляются у использованных или явно запрошенных отчётов. Явные отрицания «Не ищи» и «Не сохраняй» блокируют соответствующие эффекты. Набор языковых правил ограничен; это не универсальный разбор естественного языка.

Номера источников всегда относятся к последнему списку, показанному ассистентом. Новая тема очищает прежнюю выборку, фильтры и активный отчёт. Фильтр свежести использует период и опорную дату самого отчёта, не подменяет его новым сбором.

## Память и запись

В уже используемой SQLite-базе создаются таблицы `trend_conversations`, `trend_chat_turns`, `trend_bookmarks`. Фотографии и личные файлы в чат не загружаются. В браузере сохраняется только идентификатор выбранного диалога; сообщения остаются на backend.

Чат сохраняет готовый исследовательский отчёт, сообщения, параметры, выборку и закладки одной транзакцией. До завершения сообщения новый отчёт существует только в рабочем контексте. После транзакции отдельно расширяется архив датированных наблюдений; сбой архива не удаляет готовый отчёт.

Повтор того же `turnId` и того же запроса возвращает сохранённый результат. Тот же идентификатор с другим содержимым отклоняется. `expectedRevision` защищает от перезаписи устаревшим клиентом. На диалог допускается одно сообщение в работе, глобально — три. Отмена перед завершением не записывает сообщения, отчёты или закладки этого обмена. Синхронизация сводок разделов на сайте является отдельной операцией и может выполниться раньше отмены.

Модель ограничена шестью обращениями, десятью действиями и одним исследованием на сообщение. Последние шаги резервируются для ответа. При отказе модели доступные результаты инструментов возвращаются с явным ограничением. Срок сообщения — 115 секунд; для уже настроенного Runpod — 300 секунд. Фиксированный сценарий исследования имеет собственные ограничения времени и сети.

В одном диалоге до 100 обменов. История показывает 40 последних диалогов; данные не удаляются автоматически. Демо и live помечаются в сообщениях; чтение отчётов и закладок инструментами ограничено текущим режимом. `profileId` по-прежнему не заменяет авторизацию: API предназначен для локального прототипа.

## HTTP API

| Метод | Путь |
| --- | --- |
| GET | `/api/trends/chat/tools` — каталог операций |
| GET / POST | `/api/trends/chat/:profileId/conversations` — список / создать, тело `{reportId?}` |
| GET | `/api/trends/chat/:profileId/conversations/:id` — состояние и сообщения |
| POST | `/api/trends/chat/:profileId/conversations/:id/messages/stream` — NDJSON progress/result/error |

Сообщение содержит `turnId`, `expectedRevision`, `text`, `mode`, `enableAi`, `useWeb`, `useModuleContext`. Историю сообщений, роли system/tool и готовые отчёты клиент не передаёт. Закрытие потока отменяет незавершённую работу через AbortSignal.

## Проверки

`backend/src/tests/trend-chat-tools.test.ts` проверяет инструменты напрямую без модели: фильтры, сравнение, границы доступа, приватные темы, доступность поиска по обычной теме, запрет поиска при обсуждении сохранённых данных и запрет неявного сохранения и транзакцию.

`backend/src/tests/trend-chat.test.ts` проверяет последовательный диалог, обсуждение отчёта без нового поиска, исправление выдуманных ссылок, повторную отправку, версию диалога, отмену и HTTP-поток. Проверка идентификаторов и URL не гарантирует смысловую правильность каждой фразы или дословной цитаты в свободном ответе модели — основания и ограничения остаются доступны пользователю.
