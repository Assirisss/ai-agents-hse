# Спорт и питание

Ручной дневник работает без моделей: тренировки, питание, фотографии, самочувствие, цели и статистика. Интерфейс находится в `frontend/src/modules/health/`, API — в `backend/src/health/`, общие типы — в `shared/health.ts`, чистые расчёты — в `shared/health-math.mts`.

## Запуск

Node.js 24 LTS. В двух терминалах из корня:

```sh
cd backend
npm ci
npm run dev
```

```sh
cd frontend
npm ci
npm run dev
```

Откройте адрес Vite и раздел «Спорт и питание». Для ручного дневника ключи API и Runpod не нужны. Для тренера настройте [отдельный endpoint Runpod](health-runpod.md). SQLite автоматически создаётся в `backend/data/health.sqlite`; путь можно переопределить через `HEALTH_DB_PATH`. Каталог данных исключён из Git. Для резервной копии остановите backend и скопируйте базу; схема имеет `user_version=2`; миграция добавляет только счётчик AI-запросов.

## Возможности

- **Сегодня:** выбор даты, итоги КБЖУ, тренировки, питание и необязательное самочувствие 1–5 с заметкой.
- **Тренировки:** силовые подходы с повторениями и весом; собственный вес выделен отдельно. Кардио содержит длительность и необязательное расстояние. Есть справочник упражнений, история, редактирование, удаление с подтверждением, повтор и шаблоны.
- **Шаблоны:** копируют состав тренировки; новое выполнение независимо от исходной записи. Массовое изменение веса или повторений применяется только к черновику, с нижней границей 0 кг / 1 повторение. Готовые программы и автоматические рекомендации не генерируются.
- **Питание:** собственные продукты с КБЖУ на 100 г, порции в граммах, завтрак/обед/ужин/перекус. Продукт можно создать прямо в форме приёма пищи. Отдельно доступны ручные цели и часовой пояс.
- **Прогресс:** периоды 7/30/90 дней, графики калорий и самочувствия, таблица КБЖУ, показатели выбранного упражнения и итоги кардио.
- **Тренер:** разбор текста тренировки, фото еды или этикетки, объяснение прогресса и предложение тренировки через отдельный Runpod endpoint. Результаты проходят проверку пользователя перед сохранением; без настройки AI доступен ручной дневник.

## Правила данных и расчётов

КБЖУ порции = значение на 100 г × масса / 100. Калории берутся с введённой этикетки, а не вычисляются заново из БЖУ. Округление выполняется при отображении. Цели первоначально пустые; текущие цели используются для сравнения выбранного дня, без исторических версий целей.

Приём пищи хранит снимок названия, марки и пищевой ценности каждого продукта. Изменение или удаление продукта не меняет историю. При изменении массы уже сохранённой строки используется её прежняя пищевая ценность; чтобы применить новую, удалите строку и добавьте продукт заново. Аналогичные снимки упражнений сохраняются в тренировках и шаблонах.

Силовой объём — сумма `вес × повторения` для выбранного упражнения с отягощением. Для упражнений с собственным весом показываются подходы и повторения, введённый дополнительный вес сохраняется в журнале. Темп кардио считается только по записям с известным расстоянием; время остальных занятий входит в общую длительность. Изменённые виды одного упражнения отображаются отдельными строками. Дни без еды/самочувствия — пропуски, не нули.

Дата записи — календарная строка `YYYY-MM-DD`. «Сегодня» определяется по часовому поясу раздела, первоначально взятому из браузера; смена пояса не сдвигает существующие записи. В интерфейсе используется профиль `default`; API разделяет данные по `profileId`, но это не авторизация. Приложение остаётся локальным, без публикации в интернет.

## Фотографии

Один необязательный файл на приём пищи: неподвижный JPEG, PNG или WebP, до 6 МиБ и 40 Мп. Backend проверяет реальное содержимое через Sharp, учитывает ориентацию, уменьшает до 1600 px по длинной стороне, удаляет метаданные и сохраняет WebP. Оригинал не сохраняется.

Файл хранится BLOB-записью в той же SQLite, отдельно от JSON дневника. Изменение фото и записи транзакционно; при ошибке форма остаётся заполненной. Удаление приёма пищи удаляет вложение. Сохранение вложения отправляет фото только локальному backend. Отдельная кнопка «Разобрать» в тренере явно отправляет нормализованное фото в Runpod.

## API

Базовый путь — `/api/sport`, необязательный query-параметр `profileId=default`.

| Маршрут | Назначение |
| --- | --- |
| `GET /state` | Справочники, записи и настройки без байтов фото |
| `GET /capabilities` | Состояние подключения, `aiUnavailable` с безопасной причиной недоступности, модель, месячный счётчик, поддержка вложений |
| `GET /settings`, `PUT /settings` | Часовой пояс и цели |
| `GET/POST /{collection}`, `GET/PUT/DELETE /{collection}/:id` | `exercises`, `products`, `workouts`, `templates`, `meals`, `wellbeing` |
| `GET /summary?date=YYYY-MM-DD` | Сводка выбранного дня |
| `GET /stats?to=YYYY-MM-DD&days=30&exerciseId=...` | Статистика за 7, 30 или 90 дней |
| `GET /meals/:id/photo` | Бинарный WebP |
| `POST /assistant/:operation` | Проверенный AI-черновик либо `status: unavailable`, если AI не настроен или его настройки некорректны |

`PUT` принимает полную редактируемую запись. Для фото: отсутствие поля `photo` сохраняет прежнее вложение; `null` удаляет; строка data URL заменяет. Новые строки продуктов и упражнений получают собственные UUID; снимки справочников формирует сервер. Для копирования тренировки/шаблона передайте `source: { kind: 'workouts' | 'templates', id }` и прежние идентификаторы строк. Самочувствие уникально по профилю и дате. `/api/health` остаётся проверкой работоспособности сервера.

## Подключение моделей

[Настройка Runpod, бюджет и запуск](health-runpod.md). Интерфейс `HealthAssistant` имеет реализации `UnavailableHealthAssistant` и `RunpodHealthAssistant`; отдельный транспорт обслуживает мультимодальные запросы через официальный vLLM worker. Конфигурация других разделов не включает AI спорта автоматически. `healthAiConfiguration` разрешает отдельный ключ спорта с совместимостью для общего ключа; ошибочные AI-настройки не останавливают backend и ручной дневник. Базы данных и остальные ошибки запуска не скрываются.

Контракты запросов/ответов находятся в `shared/health.ts`, проверка входа и ответов — в `ai-schema.ts`. `POST /assistant/:operation` принимает поля соответствующего `HealthAiInput` без `operation`. КБЖУ и сохранение остаются вне модели. Для прогресса `progress.ts` рассчитывает факты и допустимые выводы, модель возвращает только `insightIds`, а весь отображаемый текст строится сервером. Внешний контракт `observations`/`facts` сохранён; неизвестные и повторяющиеся ID, лишние поля и свободный текст отклоняются. Новые продукты с этикетки создаются только после явной проверки данных; неизвестные продукты выбираются из справочника или добавляются вручную.

## Проверки

```sh
cd backend
node --import tsx --test src/tests/health*.test.ts
npm test
npm run build
```

Во frontend: `npm run lint` и `npm run build`. Автотесты покрывают снимки истории, КБЖУ, силовые и кардио, независимость шаблонов, валидацию фото, транзакции, перезапуск SQLite, профили, даты и отсутствие сетевых вызовов отключённого AI. Отдельные `health-ai.test.ts` проверяют Runpod через подставной транспорт, отмену, квоту и отсутствие автоматической записи. Регрессионные тесты дополнительно проверяют реальный запуск backend с ошибочной AI-конфигурацией, изоляцию ключей, исправление типов упражнений и невозможность передать выдуманные числа через объяснение прогресса. Полный набор содержит проверки локальных HTTP-серверов: среда должна разрешать открывать localhost.

Ручной браузерный сценарий: создать тренировку → сохранить шаблон → повторить с новым весом; создать продукт внутри формы еды → добавить 150 г и фото → сохранить → изменить до 200 г → проверить итоги и сохранность фото после обновления страницы. Дополнительно проверить недоступный backend, повтор загрузки, клавиатурное переключение вкладок и узкий экран. Проверки с тестовыми записями выполняйте в отдельной базе через `HEALTH_DB_PATH`.

Проверка исправлений 19 октября 2026: 211 backend-тестов, сборки обоих пакетов и frontend lint прошли. В Safari на изолированном стенде с временной SQLite и поддельным транспортом проверены ширины 320/390/1280 px, причина недоступности AI, исправление типа неизвестного упражнения, создание упражнения и сохранение тренировки, сохранность формы после HTTP 503, клавиатурный ввод и Escape. Продукт с 70 ккал на 100 г дал 105 ккал для 150 г и 140 ккал после изменения до 200 г; фото и тренировка сохранились после обновления страницы и перезапуска стенда. Объяснение совпало с исходными показателями; восстановление загрузки после HTTP 503 прошло. Результаты двух отдельных платных запросов приведены в [документации Runpod](health-runpod.md#проверка-нового-контракта-прогресса--19-октября-2026).

При запущенном Vite `/tests/health-preview.html` открывает настоящий раздел во фрейме шириной 320/390/768/1280 px. Стенд использует текущий backend и не входит в production-сборку. Проверены Chrome и Safari, формы на 320/390 px, переходы по вкладкам с клавиатуры и сохранение заполненной формы после сбоя сервера.
